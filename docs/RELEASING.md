# Nexus 0.2.1 release operations

The official signed manifest is at https://raw.githubusercontent.com/qemvix/nexus/main/updates/stable.json. New builds include its URL and RSA public key. Daily checks are opt-in and require Network; download/install remain explicit. The 0.2.0 client needs this URL/key configured once; its existing check/download flow opens the newer installer, which updates the installed app without uninstalling.

Run scripts/build.ps1 -Publish -Integration and formatting verification. Publish the exact tested installer/portable assets in qemvix/nexus using an immutable desktop-vVERSION tag. Never include signing keys or user settings in release assets. Generate the signed manifest against the final installer using scripts/sign-release.ps1; commit it to nexus/updates/stable.json only after public download/digest verification. Keep the identical signed envelope at NexusApp/updates/stable.json for already-installed 0.2.x clients that still use the original feed URL. Keep public/assets/release.json and download page hashes aligned with those assets.

The publisher private key is DPAPI-encrypted at %LOCALAPPDATA%\NexusPublisher\update-signing-key.dpapi and is not in either repository. scripts/sign-release.ps1 uses it by default from the same Windows user. An explicit PrivateKeyFile can use an independently secured PEM instead. Preserve the encrypted key and the Windows account/profile: the encrypted file alone is not portable to a different account or PC. Never create a replacement key silently; installed clients trust the existing public key. An export/rotation needs a deliberate recovery plan.

Manifest signing authenticates update metadata and SHA-256; it is separate from Authenticode. These preview binaries remain unsigned by Windows publisher signing. No unattended installation, cloud signing service or automatic rollback is included. Portable updates create/update a per-user installed copy. The worker waits for the old process, stages the fixed install target, preserves local settings and relaunches the hub.

CI builds/tests and packages the app; signed feed publication is a separate publisher operation requiring the protected key. Official application releases and the desktop monorepo are qemvix/nexus. Website source is qemvix/NexusApp. Nexus remains proprietary regardless of repository visibility.
## GitHub-built releases from 0.2.2

The Windows workflow runs the build, unit/native tests, formatting check and packaged screenshot capture on GitHub. A separate job creates a verified draft for a new application version in qemvix/nexus. Existing published assets are immutable and are never overwritten by a later documentation/feed build. The draft is published only after review and update-feed signing.

The workflow emits a small release-metadata artifact and a separate screenshot artifact. The publisher can sign a trusted, verified remote installer digest with `scripts/sign-release.ps1 -Sha256 <digest> -Url <official-installer-url> -Version <version> -Output <manifest>`. Only use a digest checked against the successful build's uploaded release asset. No private signing key is sent to GitHub Actions. This avoids downloading and rebuilding the installer on the publisher's PC.
